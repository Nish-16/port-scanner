# V4 – Banner Grabbing

**Status:** Complete
**Environment:** Windows 11, Python 3.13.15, standard library only
**Previous version:** [V3](V3.md)

---

## 1. V4 Goal

V3 only *guessed* the service from the port number. V4 **talks to each open service** and reads the small response it gives (the "banner"). That response is evidence that comes from the service itself.

```
Port scanning            → Is the port open?                (V1/V2, TCP level)
Service inference        → What usually runs on this port?  (V3, lookup table)
Banner grabbing          → What does the service say?       (V4, application level)
```

Out of scope, not added: version parsing, vulnerability/CVE checks, TLS handling, UDP, SYN/stealth scans, fuzzing, crawling, third-party packages.

### New constants (in `scanner.py`)

```python
MAX_BANNER_BYTES = 1024          # never read more than this
MAX_BANNER_LENGTH = 80           # never display more than this
HTTP_PORTS = {80, 8000, 8080}    # client speaks first → send HEAD
TLS_PORTS = {443}                # encrypted → skipped in V4
```

### Design decisions

| Decision | Reason |
|---|---|
| **Reuse `--timeout`** for banners (no `--banner-timeout`) | One option is simpler; the 1 s default suits both steps |
| **Two phases, two pools, one after the other** | Keeps "TCP discovery" and "application interaction" clearly separate; no nested pools; closed ports can't be contacted twice |
| **Skip TLS on 443** (`Banner unavailable (TLS)`) | A TLS handshake would add `ssl` complexity for little learning value right now |
| **One `recv()`** | We want a small identifying response, not a whole conversation |
| **Every error → `No banner`** | A single odd service must never stop the scan |
| **Printable ASCII only in output** | Found by testing (see §4.3): non-ASCII characters crashed printing on a cp1252 console |
| **Service table in `services.py`** | Requested; the list grew large enough that data and code are easier to read apart |

## 3. Architecture

```
parse + validate arguments → resolve target
        ↓
Phase 1  thread pool → scan_port() for every port      (TCP level)
        ↓
open ports (sorted)          closed ports stop here
        ↓
Phase 2  thread pool → grab_banner() for each OPEN port (application level)
        │   443 (TLS)           → skip  → "Banner unavailable (TLS)"
        │   80 / 8000 / 8080    → connect → send HEAD → recv(1024)
        │   everything else     → connect → recv(1024)
        │   any error/timeout   → "No banner"
        ↓
clean_banner(): decode safely → printable ASCII → join lines with " | " → cut to 80 chars
        ↓
main: (port, guess_service(port), banner)   ← guess from services.py (port number only)
        ↓
sorted table + summary (Open ports, Banners found, Time taken)
```

The HTTP probe sent is exactly:

```
HEAD / HTTP/1.0\r\nHost: <ip>\r\nConnection: close\r\n\r\n
```

HEAD returns only headers: no page download, no redirects followed.

### 4.3 Bug found and fixed during testing

The first run **crashed** with `UnicodeEncodeError` while printing a banner containing `�`:

- `errors="replace"` made decoding safe, but the resulting text still contained non-ASCII characters.
- With output redirected, Windows Python prints using **cp1252**, which can't encode `�`.
- **Fix:** `clean_banner()` now keeps only printable ASCII and turns any other character into `?`.
- **Lesson:** safe *decoding* isn't enough; the output also has to be safe for whatever terminal or file it's written to.

## 5. Performance

Real services only, localhost, no test listeners. V3 was run from a saved copy of the V3 code.

| Range | Timeout | Threads | Open ports | V3 time | V4 time | Extra | Banners |
|---|---|---|---|---|---|---|---|
| 1–1024 | 1.0 s | 100 | 2 | 11.11 s | 12.12 s | +1.01 s | 0 |
| 1–65535 | 0.2 s | 500 | 47 | 28.47 s | 28.74 s | +0.27 s | 2 |

- V4 is **slower**, as expected, because it does more work.
- Because banners are grabbed **in parallel**, the extra cost is roughly **one timeout** (the time silent services make us wait), not one timeout per open port.
- A later run after the `services.py` change took 12.14 s (1–1024) and 28.70 s (1–65535). The table change doesn't affect speed.

## 6. Lessons

- **Banner vs port inference:** `8080 → HTTP-Alt` comes from our table; `HTTP/1.0 200 OK` comes from the service. A banner is stronger evidence, but can still be hidden, faked, customised or incomplete. Port 2222 showed `UNKNOWN` with an SSH banner, so the two are independent.
- **Server-speaks-first vs client-speaks-first:** SSH, MySQL and the EA service greet immediately, so `connect()` + `recv()` works. HTTP waits for a request, so we must `send()` a HEAD first. A client-speaks-first service on an unexpected port just shows `No banner`.
- **Bytes vs strings:** `recv()` returns `bytes`. Decoding turns them into `str`. Not all services send text (MySQL's greeting is binary), so decoding uses `errors="replace"`.
- **Timeouts:** without a timeout, `recv()` on a silent service would wait forever. With one, the silent test listener gave `No banner` after 0.5 s. The same timeout also limits how long Ctrl+C takes in phase 2.
- **Safe output:** remote data is untrusted. Control characters (ESC, bell, tab, NUL) are dropped so a banner can't clear the screen or recolour the terminal. Output is ASCII-only, one line, and at most 80 characters.
- **Resource cleanup:** every banner socket lives in a `with` block. After Ctrl+C, no worker threads remain. The `FIN_WAIT_2` entries seen after interrupting against silent test servers are **OS-level half-closed connections**: our side closed and sent FIN, but the test server never closed its side. The OS clears them itself. Against normal services the count went back to 0.

## 7. Limitations

V4 is **basic banner grabbing**, not a service/version detector:

- Only reads what a service sends first; sends HEAD only to 80/8000/8080
- No TLS: HTTPS shows `Banner unavailable (TLS)`, and other TLS ports (993, 995, 8443…) show `No banner`
- One `recv()`: a banner split across packets may be cut short
- Banners aren't parsed or verified; versions aren't extracted
- Binary protocols show partly as `?` characters
- `services.py` is a curated list of 92 ports, not the IANA registry
- TCP only, IPv4 only, can't tell closed from filtered
